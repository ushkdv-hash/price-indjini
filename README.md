# Калькулятор на Apploy

Это та же программа, что в `release/` (Amvera), но упакованная под Apploy:
Docker-образ, `docker-compose.yml` и манифест платформы.

Apploy **не понимает `amvera.yml`** и не умеет загружать папку архивом: он клонирует
Git-репозиторий и запускает приложение в контейнере. Поэтому одной папки `release/`
для Apploy недостаточно — нужен этот пакет. Код приложения при этом не менялся:
`app.py`, `wsgi.py`, шаблоны, стили и справочники те же самые.

## Что внутри

```text
release-apploy/
├── Dockerfile                  — образ Python 3.12 + gunicorn
├── docker-compose.yml          — запуск и постоянный том /data
├── docker-entrypoint.sh        — секретный ключ, инициализация, запуск
├── apploy-manifest.json        — шаблон манифеста для панели
├── .dockerignore
├── .gitignore
├── README.md                   — этот файл
├── app.py, wsgi.py
├── offset_lib.py, wide_format_lib.py, import_omega_prices.py
├── templates/, static/
├── data/                       — справочники прайса (без пользователей и истории)
└── requirements.txt
```

## Что понадобится

1. Аккаунт Apploy и машина в состоянии «работает» (подписка или заказанная ВМ).
2. Git-репозиторий на GitHub, GitLab, Gitea или своём сервере.
3. 5–10 минут на первую сборку.

Публичный репозиторий проще: не нужен токен. Приватный тоже подходит — токен
задаётся отдельно в карточке приложения и в манифест не попадает.

## Шаг 1. Положите пакет в Git

Содержимое папки `release-apploy/` должно лежать в репозитории. Два варианта:

**Вариант А — репозиторий только под калькулятор (проще).**

```bash
cd release-apploy
git init
git add .
git commit -m "Калькулятор для Apploy"
git branch -M main
git remote add origin https://github.com/ВАШ-ЛОГИН/auto-price.git
git push -u origin main
```

Тогда в манифесте `"subdir": "."`.

**Вариант Б — пакет лежит в существующем репозитории подпапкой.**

Например, в репозитории есть папка `apploy/` с этими файлами. Тогда в манифесте:

```json
"subdir": "apploy",
"compose_file": "docker-compose.yml"
```

Файл `docker-compose.yml` должен находиться именно в `subdir`.

Проверьте, что в репозиторий **не попали**:

- `.env`;
- `data/users.json`, `data/history.json`, `data/user_activity.json`,
  `data/news.json`, `data/news_reads.json`.

Они перечислены в `.gitignore`. Эти файлы должны жить только в томе на сервере.

## Шаг 2. Добавьте приложение в панели

1. Откройте **Контейнеры** (или **Приложения**) и выберите машину.
2. В блоке манифеста вставьте JSON ниже.
3. Замените `repo_url` на адрес своего репозитория (кнопка **Code → HTTPS**,
   адрес оканчивается на `.git`).
4. Если основная ветка называется `master`, поправьте `branch`.
5. Нажмите **Сохранить манифест**.

```json
{
  "app": "auto-price",
  "repo_url": "https://github.com/USERNAME/auto-price.git",
  "branch": "main",
  "subdir": ".",
  "compose_file": "docker-compose.yml",
  "health_url": "http://127.0.0.1:8080/login",
  "health_timeout": 10.0
}
```

Имя `app` — только строчные латинские буквы, цифры, `-` и `_`, до 32 символов.
Оно же станет префиксом контейнеров и томов (`apppilot-auto-price`).

### Приватный репозиторий

В карточке приложения есть отдельное поле **Токен** (и необязательный **Логин**).
Токен нужен только на чтение:

- **GitHub**: Settings → Developer settings → Personal access tokens →
  Fine-grained tokens → Contents: **Read-only**.
- **GitLab**: Settings → Access tokens → роль Reporter, область `read_repository`.

Токен хранится на машине, в манифест и в панель не попадает.

## Шаг 3. Соберите и запустите

По порядку, кнопками в панели:

1. **Клонировать репозиторий** — в журнале будет хеш коммита.
2. **Собрать образ** — первая сборка 2–5 минут (ставится Python и библиотеки).
3. **Запустить всё** — контейнер должен перейти в состояние `running`.
4. **Health-check** — должен ответить `200` по адресу
   `http://127.0.0.1:8080/login`.

В журнале приложения при старте будут строки:

```text
[auto-price] SECRET_KEY создан: /data/.secret_key
[auto-price] DATA_DIR=/data bundled=/app/data persistent=True
[auto-price] Запуск gunicorn: 0.0.0.0:80, воркеров: 2
```

Строка `persistent=True` и `DATA_DIR=/data` означают, что данные пишутся в
постоянный том, а не в образ. Это главное, что нужно проверить.

## Шаг 4. Откройте приложение

В кабинете у приложения появится адрес вида:

```text
http://185.133.42.82:8080
```

Откройте его. Первый вход:

- логин: **admin**
- пароль: **admin**

**Сразу смените пароль** в разделе «Пароль».

Дальше сотрудники могут регистрироваться сами через `/register`, а вы
подтверждаете заявки в разделе **«Админка» → «Заявки на регистрацию»**.
Можно и сразу создать пользователей в разделе **«Сотрудники»**.

## Где хранятся данные

Все рабочие файлы лежат в именованном томе `appdata`, он подключён к `/data`
внутри контейнера:

```text
/data/users.json          — логины, пароли, роли
/data/history.json        — история расчётов
/data/user_activity.json  — статистика входов и расчётов
/data/news.json           — новости
/data/news_reads.json     — отметки о прочтении
/data/.secret_key         — ключ сессий (создаётся автоматически)
```

Справочники (`products.json`, `materials.json`, `works.json`, `settings.json`,
`design.json` и остальные) лежат в образе в `/app/data` и при каждом старте
копируются в `/data`. Поэтому обновление прайса из Git подхватывается, а
пользователи и история не затираются.

> **Важно про цены.** Справочники из репозитория — источник истины. Если
> поменять цену в админке, она сохранится в `/data` и будет работать до
> перезапуска контейнера. После перезапуска или пересборки значение вернётся
> к тому, что лежит в Git. Постоянные изменения цен вносите в `data/*.json`
> и коммитьте в репозиторий. Пользователи, история, статистика и новости
> при этом не затрагиваются.

Том переживает:

- пересборку образа;
- перезапуск и пересоздание контейнера;
- обновление кода из Git.

Том **не переживает** команду **«Удалить приложение»** — она удаляет контейнеры
вместе с томами. Не удаляйте приложение, если хотите сохранить пользователей.

### Резервная копия

На подписке Apploy нет SSH-доступа к машине, поэтому скопировать том вручную
нельзя. Варианты:

- не удалять приложение и не менять тому имя (`appdata`);
- периодически выгружать нужные отчёты из раздела «История»;
- если резервные копии критичны — заказать ВМ Apploy: там есть root и SSH,
  и том можно скопировать обычным `tar`.

На заказанной ВМ копия делается так:

```bash
docker run --rm \
  -v apppilot-auto-price_appdata:/data:ro \
  -v "$PWD":/backup \
  alpine tar czf /backup/data-backup.tgz -C /data .
```

Точное имя тома подскажет `docker volume ls`.

## Обновление приложения

1. Внесите правки, закоммитьте и отправьте в Git:

   ```bash
   git add .
   git commit -m "Обновление"
   git push
   ```

2. В панели: **Клонировать репозиторий** → **Собрать образ** →
   **Перезапустить всё** → **Health-check**.

Пользователи, история и настройки останутся на месте: они в томе, а не в образе.

Если менялись только шаблоны или `app.py`, пересборка всё равно нужна — код
копируется в образ при сборке.

## Домен и HTTPS

По умолчанию приложение публикуется на порту **8080** и работает по **HTTP**:

```text
http://<адрес машины>:8080
```

Это нормально для внутреннего сервиса, но пароль по открытому HTTP идёт без
шифрования. Для постоянной работы в интернете лучше HTTPS.

У заказанной машины Apploy есть технический домен `z<номер>.apploys.ru` и
сертификат Let's Encrypt на порты 80/443. Чтобы приложение отвечало по
`https://z<номер>.apploys.ru/`:

1. В `docker-compose.yml` замените публикацию порта:

   ```yaml
   ports:
     - "80:80"
   ```

2. В блоке `environment` поставьте:

   ```yaml
   PRODUCTION: "1"
   ```

   Это включает `Secure`-cookie — по HTTPS это правильно, по HTTP вход
   перестанет работать.

3. В панели: **Клонировать репозиторий** → **Собрать образ** →
   **Перезапустить всё**.

4. Откройте `https://z<номер>.apploys.ru/`.

Если порт 80 на машине занят страницей-заглушкой и контейнер не поднимается,
верните `8080:80` и обратитесь в поддержку Apploy — порт 80 освобождают они.

Свой домен направляется A-записью на IP машины; сертификат для него платформа
не выпускает. Для своего домена удобнее поставить перед приложением nginx или
Caddy с HTTPS, но на подписке это отдельная задача.

## Секретный ключ

`SECRET_KEY` нужен Flask для подписи cookie сессий. В этой сборке он создаётся
автоматически при первом запуске и хранится в `/data/.secret_key`.

Плюсы: ничего не нужно настраивать, ключ не попадает в Git, после пересборки
сессии не сбрасываются.

Если вы хотите задать ключ сами, передайте его через карточку секретов
приложения (переменная `SECRET_KEY`). Тогда файл `.secret_key` не создаётся.

## Ресурсы

Минимальный тариф «Биллдий» (0.5 vCPU, 256 МБ, 0.5 ГБ диска) подходит для
пробы и небольшого числа пользователей. Если памяти не хватает, уменьшите
число воркеров в `docker-compose.yml`:

```yaml
WEB_WORKERS: "1"
```

Для постоянной работы с несколькими сотрудниками лучше план с 1 ГБ памяти:
два воркера gunicorn и импорт Excel заметно отзывчивее.

## Обновление прайса

Прайс — это файлы `data/*.json` в репозитории. Порядок:

1. Обновите JSON локально (импорт из Excel, `build_data.py` и т.п.).
2. Закоммитьте и отправьте в Git.
3. **Клонировать репозиторий** → **Собрать образ** → **Перезапустить всё**.

При старте новые справочники скопируются в `/data`. Файлы пользователей,
истории, статистики и новостей не затрагиваются.

## Если что-то не работает

**«compose-файл не найден»**

Проверьте `subdir` и `compose_file`. Файл должен называться
`docker-compose.yml` или `compose.yml` и лежать в указанной подпапке
размножаемого репозитория.

**«ветка не найдена»**

В манифесте `main`, а в репозитории `master` (или наоборот). Посмотрите имя
основной ветки на странице репозитория.

**Контейнер перезапускается**

Откройте **Логи**. Чаще всего это:

- нет доступа к репозиторию (приватный без токена);
- ошибка в `Dockerfile` или `docker-compose.yml`;
- не хватает памяти.

**Health-check не отвечает**

Проверьте, что в `docker-compose.yml` осталось `"8080:80"`, а `health_url` —
`http://127.0.0.1:8080/login`. Внутри контейнера приложение слушает `0.0.0.0:80`,
снаружи порт 8080.

**После входа сразу выкидывает**

Если вы включили `PRODUCTION: "1"`, а открываете по `http://...:8080`,
браузер не отправит `Secure`-cookie. Верните `PRODUCTION: "0"` или переходите
на HTTPS.

**Пропали пользователи после обновления**

Значит, приложение писало не в том. Посмотрите в логах строку:

```text
[auto-price] DATA_DIR=/data ... persistent=True
```

Если `DATA_DIR` другой или `persistent=False` — проверьте том `appdata:/data`
и переменную `DATA_DIR` в `docker-compose.yml`. Не запускайте контейнер
вручную без `-v appdata:/data`.

**«Удалить приложение»**

Эта команда удаляет и том с пользователями. Восстановить данные можно только
из резервной копии. Для обновления используйте «Пересобрать», а не «Удалить».

## Чем отличается от `release/`

| | `release/` | `release-apploy/` |
|---|---|---|
| Платформа | Amvera | Apploy |
| Конфигурация | `amvera.yml` | `docker-compose.yml` + манифест |
| Запуск | gunicorn, порт 80 | gunicorn в контейнере, наружу 8080 |
| Постоянные данные | `/data` (Amvera) | том `appdata` → `/data` |
| Секретный ключ | переменная `SECRET_KEY` | создаётся в `/data/.secret_key` |
| Код приложения | одинаковый | одинаковый |

Обе сборки можно поддерживать одновременно, но это два разных репозитория
(или две папки в одном репозитории с разными `subdir`).

## Если нужен полный контроль

Вместо подписки можно заказать у Apploy виртуальную машину: там есть root и
SSH. На неё ставится Docker, и этот же пакет запускается командой:

```bash
docker compose up -d --build
```

Разницы в приложении нет — только в способе управления сервером.
